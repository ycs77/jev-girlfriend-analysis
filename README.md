# 對話求生慾即時警報器

基於 [typesafe.ai](https://typesafe.ai) 的 **Jev System One 模型** 建立的實驗專案。它以 Jev 回傳的型別化判斷，分析關係訊息中的可觀察溝通訊號、情緒張力、需求與界線，協助使用者決定較合適的回覆方向。

專案提供兩支訊息分析腳本：一支處理目前交往中女友的訊息，另一支處理前女友的訊息。

判讀只根據你主動提供的訊息與脈絡。它不判定對方「真正的內心想法」，也不把簡短、冷淡或不想回覆自動視為生氣。資訊不足時，結果會明確提醒你不要腦補。

## 安裝

需要 Node.js 20 或更新版本，以及 `TYPESAFE_API_KEY` 環境變數。

```sh
npm install
cp .env.example .env
```

在 `.env` 設定 `TYPESAFE_API_KEY`。

## 選擇對應腳本

### 女友：`girlfriend.ts`

用於仍在交往的關係。它額外識別陪伴需求、協調安排、期待落差，以及以文字與脈絡估算的女友心情指數與反話提示。

```sh
npm run girlfriend -- "你不是說忙完會打給我嗎？" "原本約好晚上九點通話，但我延後了兩小時且沒有告知"
```

### 前女友：`ex-girlfriend.ts`

用於已結束交往關係。它額外識別交接、分手後界線，以及重新連結或尋求支持的訊號。

```sh
npm run ex-girlfriend -- "你的兩箱書我放管理室了，這週方便拿走嗎？" "已分手，物品待交接"
```

請依關係狀態選擇對應腳本。

## 輸出內容

| 欄位 | 意義 |
| --- | --- |
| 主要溝通訊號 | 將訊息歸為腳本關係情境下的可觀察型態。這是訊息型態，不是內心動機。 |
| 對話摩擦 | 回覆方式讓對話升高的可能性；不是對方的憤怒指數或人格評價。 |
| 女友心情指數 | 女友腳本專用的 0～100 情緒張力指標，綜合 Jev 對語氣與反話的獨立評估；不是對真實心情、人格或動機的事實判定。 |
| Jev 反話評估 | Jev 根據完整訊息與脈絡判斷字面意思是否可能與溝通意圖有落差；不依賴固定字詞比對。 |
| 情境資訊完整度 | 判斷已提供脈絡是否足夠。完整度或模型把握度低時，不應對動機下結論。 |
| 明確界線訊號（前女友腳本） | 前女友腳本才會判斷是否明確要求停止、限制或改變聯絡、話題、見面或溝通管道。 |
| 安全或騷擾界線（前女友腳本） | 前女友腳本才會判斷明確拒絕不受歡迎的接觸、脅迫、跟蹤、騷擾或人身安全。 |
| 建議下一步 | 依照可觀察訊號提供低壓力、尊重界線的回覆原則。程式不會替你傳送訊息。 |

Jev 模型的把握度表示候選訊息型態之間是否有明顯差異，不代表模型知道事實。前女友腳本的安全與界線判斷採保守門檻；有不確定性時，優先補充脈絡或直接確認。女友心情指數僅用於提醒回覆時放慢與確認，不取代直接溝通。

## 範例情境

| 腳本 | 訊息 | 可提供的脈絡 | 合理的判讀方向 |
| --- | --- | --- | --- |
| 女友 | 「你不是說忙完會打給我嗎？」 | 原本約好通話但未告知延後 | 協調安排或直接回饋；確認具體時間並承認等待造成的影響。 |
| 女友 | 「我今天工作被主管罵得很慘，想跟你講一下」 | 無近期衝突 | 需要連結或支持；先確認自己是否有餘裕傾聽。 |
| 女友 | 「我現在不想討論誰對誰錯，晚點再說」 | 爭執中 | 暫停對話的界線，不應貼上負面標籤。 |
| 女友 | 「那你先忙」 | 你已經兩小時沒有回覆，原本說好要一起選餐廳 | 可能有等待或期待落差；先確認能回覆的時間，不要假定對方一定生氣。 |
| 女友 | 「隨便你」 | 正在討論你是否要和朋友出門 | 由 Jev 依脈絡評估是否有表面允許的落差，仍需詢問她在意的具體問題。 |
| 前女友 | 「你的兩箱書我放管理室了，這週方便拿走嗎？」 | 已分手、物品待交接 | 實際交接，不要解讀成試探。 |
| 前女友 | 「今天經過那間麵店，還是會想到以前每次都點錯餐」 | 無近期衝突 | 重新連結訊號，但不應直接認定要求復合。 |
| 前女友 | 「之後共同帳務請寄 email，其他事不用再傳訊息給我」 | 分手交接中 | 尊重指定管道，不要用更多訊息要求互動。 |
| 前女友 | 「聽說你最近換新工作了？看來沒有我之後，你過得越來越順遂了嘛～」 | 你剛發布新工作的動態 | 可能有近況刺探或間接不滿；不要替對方下定論，先依實際關係與意願決定是否回覆。 |
| 前女友 | 「你把 Netflix 密碼改掉了喔？我都不能看了」 | 先前曾共用帳號，現在已分手 | 可能是帳號交接或直接回饋；先釐清先前約定與實際需求。 |
| 前女友 | 「下個月周杰倫演唱會，你應該買到票了吧？」 | 以前曾說好要一起看 | 可能在提起共同計畫或確認近況，不應直接視為要求復合。 |
| 前女友 | 「我電腦突然開不起來，裡面有明天要交的報告，你可以幫我遠端看一下嗎？」 | 對方知道你熟悉電腦 | 明確的協助請求；可依自己的界線決定是否協助。 |
| 前女友 | 「如果那時候我們都沒有那麼脾氣硬，現在會不會不一樣？」 | 分手後深夜傳來，近期沒有衝突 | 可能是重新連結或情緒支持訊號；先確認自己願意進行哪種互動。 |
| 任一腳本 | 「好」 | 沒有前文 | 不推定情緒；要求補充前文。 |
| 前女友 | 「請不要再到我公司等我；再發生我會請公司處理」 | 有不受歡迎的接觸 | 停止所有非必要接觸，優先遵守安全與界線。 |

## 女友心情指數與 Jev 反話評估

女友腳本把情緒張力拆成兩個由 Jev 獨立回答的問題：

- **語氣模型，最高 70 點**：依訊息與使用者提供的脈絡評估不滿、受傷、焦慮、期待落差或需要被關心的表達強度。
- **反話評估，最高 30 點**：依完整訊息與脈絡評估字面意思和可能溝通意圖是否有落差，並辨識表面允許、表面沒事、表面體貼或抽離等模式。

程式不會用固定字詞比對自動加分；Jev 會收到反話範例及其可能含義作為判斷參考，包括表面允許、表面沒事、表面降低需求、結束話題與表面體貼或抽離。它仍必須根據完整訊息與脈絡判斷是否適用；脈絡不足時，結果應維持低把握度或資訊不足。

提供給 Jev 的範例涵蓋「去啊」、「隨便你」、「你高興就好」、「不用陪我沒關係」、「沒事」、「我很好」、「算了」、「你想太多了」、「那你先忙」、「不打擾你了」與「你慢慢來，我不急」。每一則都只描述**可能**的溝通含義，例如期待被納入考量、暫時不想表達感受、想結束話題或感到被忽略，並非對對方內心的定論。

收到 Jev 的反話評估時，先確認具體事件與感受，例如「我感覺這件事可能讓你不舒服，想聽你怎麼看」。不要把評估當成事實、直接取消行程或替對方做決定。

## 使用原則

- 不要因為單一字詞、單一標點或極短訊息就認定對方生氣；沒有前後文時，它們都是低資訊訊號。
- 有具體事件時，先回應事件造成的影響；不要用猜測動機取代道歉、說明或詢問。
- 對方設下聯絡或互動界線時，尊重界線比爭取立即回覆更重要。
- 前女友腳本出現明確安全、騷擾或脅迫訊號時，停止把問題當成戀愛攻略；優先避免非必要接觸並尋求適當支援。
- 你可以關心對方，但不需要承諾超出自己能力或界線的互動。
