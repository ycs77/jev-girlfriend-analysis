# 對話求生慾即時警報器

基於 [typesafe.ai](https://typesafe.ai) 的 **Jev System One 模型**建立的實驗專案。它根據你提供的訊息與脈絡，輸出對方**可能的心情狀態**與一項可直接採取的行動。

專案提供兩支腳本：一支處理目前交往中女友的訊息，另一支處理前女友的訊息。

## 安裝

需要 Node.js 20 或更新版本，以及 `TYPESAFE_API_KEY` 環境變數。

```sh
npm install
cp .env.example .env
```

在 `.env` 設定 `TYPESAFE_API_KEY`。

## 選擇對應腳本

### 女友：`girlfriend.ts`

用於仍在交往的關係。高心情指數時，建議會優先處理約定落空、衝突、想被傾聽或需要暫停互動的情境；文字與脈絡共同顯示可能有反話時，建議會改為先確認她真正比較在意的事。

```sh
npm run girlfriend -- "你不是說忙完會打給我嗎？" "原本約好晚上九點通話，但我延後了兩小時且沒有告知"
```

### 前女友：`ex-girlfriend.ts`

用於已結束交往關係。建議會優先限制回覆範圍：只處理交接與共同責任、尊重聯絡界線，不把回憶或近況直接視為復合邀請。

```sh
npm run ex-girlfriend -- "你的兩箱書我放管理室了，這週方便拿走嗎？" "已分手，物品待交接"
```

請依關係狀態選擇對應腳本。

## 輸出內容

兩支腳本都輸出心情指數與一項可直接採取的行動；女友腳本會另外輸出 Jev 對溝通訊號的有條件判讀。

| 欄位 | 意義 |
| --- | --- |
| 心情指數 | 0～100 的文字情緒張力估計，以及白話摘要。它表示訊息**可能**呈現的狀態，不是對方真實內心、人格或動機的事實判定。 |
| Jev 判讀 | 僅女友腳本輸出。說明訊息是否可能呈現表面放行、表面沒事、表面體貼或直接不滿等溝通訊號；證據不足時會明說無法判定。 |
| 建議行動事項 | 依關係狀態與訊息情境給出一項可直接採取的回覆方向。程式不會替你傳送訊息。 |

心情指數的白話區間：

| 分數 | 白話摘要 |
| --- | --- |
| 0～24 | 看起來平穩 |
| 25～49 | 可能有點在意或有感觸 |
| 50～74 | 可能不舒服、失望或關係緊繃 |
| 75～100 | 可能明顯生氣或高度不舒服 |

沒有足夠脈絡，且文字本身沒有明確情緒、請求或界線時，程式會顯示「無法可靠判讀」，不會硬塞一個心情分數。

## 女友的溝通訊號判讀

女友腳本會在同一個 Jev 請求中平行判斷訊息情境、情緒張力、溝通訊號和回覆重點。它會考慮下列可能的字面與在意事項落差：

- **表面放行**：看似同意去做某事，但脈絡顯示更在意陪伴、被商量或共同決定。
- **表面沒事**：看似說沒關係或算了，但脈絡顯示仍有未處理的事件、期待或受傷感。
- **表面體貼**：看似叫對方先忙、慢慢來或不打擾，但脈絡顯示可能在意被延後、忽略或沒有主動更新。

驚嘆號、問號、訊息長度與簡短回覆也是 Jev 可參考的語氣線索，但不會以固定關鍵字或標點規則直接加分。短句、單一標點或沒有前後文的「沒事」、「隨便你」都不會直接被判定為生氣。

## 範例情境

| 腳本 | 訊息 | 可提供的脈絡 | 合理的判讀方向 |
| --- | --- | --- | --- |
| 女友 | 「你不是說忙完會打給我嗎？」 | 原本約好通話，但沒有告知延後 | 處理期待落差；承認等待造成的影響，並確認具體時間。 |
| 女友 | 「我今天工作被主管罵得很慘，想跟你講一下」 | 無近期衝突 | 可能需要傾聽或支持；先確認她想被陪伴，還是一起想辦法。 |
| 女友 | 「我現在不想討論誰對誰錯，晚點再說」 | 爭執中 | 這是暫停對話的界線；不要持續追問或反駁。 |
| 女友 | 「那你先忙」 | 你已兩小時沒有回覆，原本說好要一起選餐廳 | 可能有等待或期待落差；先確認能回覆的時間，不要假定她一定生氣。 |
| 女友 | 「隨便你」 | 正在討論你是否要和朋友出門 | 由 Jev 依脈絡判讀是否有表面放行的落差；先確認她在意的具體問題。 |
| 女友 | 「去啊」 | 你提議臨時和朋友聚會，原本約好一起吃晚餐 | 可能是表面放行；先確認原本的約定和她是否仍希望一起安排。 |
| 女友 | 「你高興就好」 | 你自行決定週末行程，沒有先和她討論 | 可能在意沒有被納入考量；先詢問她對安排的想法。 |
| 女友 | 「不用陪我沒關係」 | 她剛提過今天心情不好，你準備去打電動 | 可能表面降低需求；先確認她是否希望被陪伴或晚點聊聊。 |
| 女友 | 「沒事」 | 你忘了原本答應要處理的事 | 可能是表面沒事；先承認事件，並問她受到什麼影響。 |
| 女友 | 「我很好」 | 你察覺她回覆變少，先前剛有爭執 | 可能暫時不想表達感受；不追問逼答，留一個可回覆的關心。 |
| 女友 | 「算了」 | 正在重複討論同一件失約或誤會 | 可能想結束沒有進展的討論；先停止辯解，回應具體事件。 |
| 女友 | 「你想太多了」 | 你問她是否因為行程改動而不開心 | 仍有多種解讀；不要把它直接當反話，可確認事件和感受。 |
| 女友 | 「不打擾你了」 | 你數小時未讀，原本說忙完會回覆 | 可能表面體貼但在意被忽略；給出能回覆的具體時間。 |
| 女友 | 「你慢慢來，我不急」 | 她已等候你確認出門時間一段時間 | 可能在意延後或沒有更新；主動說明進度並給出確定時間。 |
| 前女友 | 「你的兩箱書我放管理室了，這週方便拿走嗎？」 | 已分手，物品待交接 | 實際交接；只確認物品、時間與聯絡方式。 |
| 前女友 | 「今天經過那間麵店，還是會想到以前每次都點錯餐」 | 無近期衝突 | 可能是分享回憶；不要直接解讀成復合邀請。 |
| 前女友 | 「之後共同帳務請寄 email，其他事不用再傳訊息給我」 | 分手交接中 | 尊重指定管道與範圍；只在必要時處理明確事項。 |
| 前女友 | 「聽說你最近換新工作了？看來沒有我之後，你過得越來越順遂了嘛～」 | 你剛發布新工作的動態 | 可能是近況刺探或間接不滿；不替對方下定論，依實際關係與意願決定是否回覆。 |
| 前女友 | 「你把 Netflix 密碼改掉了喔？我都不能看了」 | 先前曾共用帳號，現在已分手 | 可能是帳號交接或直接回饋；先釐清先前約定與實際需求。 |
| 前女友 | 「下個月周杰倫演唱會，你應該買到票了吧？」 | 以前曾說好要一起看 | 可能在提起共同計畫或確認近況；不應直接視為要求復合。 |
| 前女友 | 「我電腦突然開不起來，裡面有明天要交的報告，你可以幫我遠端看一下嗎？」 | 對方知道你熟悉電腦 | 明確的協助請求；依自己的界線決定是否協助。 |
| 前女友 | 「如果那時候我們都沒有那麼脾氣硬，現在會不會不一樣？」 | 分手後深夜傳來，近期沒有衝突 | 可能有重新連結或情緒支持需求；先確認自己願意進行哪種互動。 |
| 任一腳本 | 「好」 | 沒有前文 | 不推定情緒；要求補充前文。 |
| 前女友 | 「請不要再到我公司等我；再發生我會請公司處理」 | 有不受歡迎的接觸 | 停止所有非必要接觸，優先遵守安全與聯絡界線。 |

## 使用原則

- 只有對方直接寫出「我很生氣」、「我很難過」等情緒時，才可把它視為文字明示的情緒。
- 「好」、「沒事」、「隨便你」、單一標點或貼圖，沒有脈絡時不會直接判成生氣。
- 女友腳本的高分代表先放慢回應、處理具體事件與感受；不代表她一定生氣。
- 前女友腳本的高分代表先不要擴大互動；不代表她想復合、討厭你或一定不想回覆。
- 前女友出現明確拒絕聯絡、安全、騷擾、跟蹤或脅迫訊號時，建議行動會優先要求停止非必要接觸並遵守界線。
